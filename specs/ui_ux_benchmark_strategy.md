# UI / UX・演出ベンチマーク戦略

更新日: 2026-08-06

## 1. 目的

TRIBE: NEON REIGN は、かつてブラウザソーシャルゲームのGvGに熱中したプレイヤーが、現在の生活リズムでも短時間に「所属」「抗争」「成長」を楽しめる縦画面ブラウザゲームを目指す。

UI改修は単なる見栄えの改善ではなく、以下を同時に満たすことを目的とする。

- 抗争に参加して組織へ貢献する高揚感を伝える。
- 忙しい日でも短時間で放置報酬、育成、編成、1戦を完了できる。
- 30代半ばから40代半ばの男女が、情報を無理なく読み取り片手で操作できる。
- 現代アウトロー、格闘技、ヤンキー、極道、夜の世界という題材を、固有のネオン表現で再解釈する。

## 2. 想定ユーザー

- 30代半ばから40代半ばの男女。
- アウトロー、格闘技、ヤンキー、極道、夜の世界を好む。
- 15年前から20年前のブラウザソーシャルゲームで、ギルド戦・GvG・ランキング競争を経験した。
- 成長、収集、組織への貢献は好むが、長時間の拘束は避けたい。

## 3. ベンチマーク・マトリクス

| 領域 | 主ベンチマーク | 参照する原則 |
| --- | --- | --- |
| GvG・ギルド抗争 | ギャングロードジョーカー、戦国炎舞、任侠伝、拳極 | 所属感、開催時間の緊張、個人貢献、勢力順位、仲間と共有する戦況 |
| 格闘・対決の熱量 | 刃牙 THE STRONGEST PROOF、拳極、喧嘩道、クローズ×WORST | 一撃の重さ、対決前の緊張、勝敗の重さ、太い漢字、荒々しい衝撃表現 |
| 必殺技・獲得演出 | ドラゴンボールZ ドッカンバトル、刃牙 THE STRONGEST PROOF | 溜め、決め、余韻の三段構成。高レアだけを強く見せる緩急 |
| 放置・育成・日課 | 放置少女 | 短時間の報酬受取、成長確認、編成、収集への導線 |
| 縦画面可読性 | Pokémon TCG Pocket、Marvel Snap | 片手操作、明快な状態表現、短い解決演出。主題材ではなく補助参照 |

ベンチマークは体験原則の参照に限定する。固有のアート、キャラクター、文言、画面構成、効果素材を複製しない。

## 4. 共通ビジュアル方針

### 4.1 世界観

- 夜の歓楽街、濡れた路面、雑居ビル、看板、勢力の縄張りを基調にする。
- 黒、鉄、くすんだ金、深い赤、シアンネオンを基調色とする。
- SFの細いパネル群ではなく、金属プレート、看板、札、スタンプのような重量感を持たせる。

### 4.2 情報階層

各画面で最初に読ませる情報は一つに絞る。

1. 現在の目的（受取、育成、侵攻、編成など）
2. その目的の結果（報酬、強化値、戦況、勝敗）
3. 次の行動

補助説明、詳細数値、履歴は常時表示せず、詳細モーダルまたは展開領域に逃がす。

### 4.3 文字・状態表現

- 見出し、勝敗、撃破、抗争開始、報酬では太い漢字と短い決め文句を使う。
- 通常文は読みやすい日本語フォントと十分なコントラストを維持する。
- 色だけに依存せず、ラベル、アイコン、数値、動きで状態を示す。

## 5. バトル演出方針

サーバー確定の再生結果を正本とし、演出は結果を分かりやすく気持ちよく伝えるために使う。

| 層 | 目安 | 表現 |
| --- | --- | --- |
| 通常攻撃 | 0.3〜0.5秒 | 前進、攻撃線、命中フラッシュ、ダメージ数値 |
| 通常スキル | 0.6〜0.9秒 | 属性色、短いスキル名、対象表示、状態異常アイコン |
| 固有・高レアスキル | 1.2〜1.8秒 | 一瞬の暗転、立ち絵カットイン、固有色、専用SE、強い命中演出 |
| 決定イベント | 0.5〜1.0秒 | 撃破、ブレイク、クリティカル、回復、フェーズ移行、GvG陥落 |
| リザルト | 即時表示 | 勝敗、総ダメージ、最大ダメージ、キャラ別貢献、報酬。詳細ログは任意展開 |

避けること:

- 全スキルで全画面演出を行うこと。
- 演出中にHP、残り時間、勝敗条件を読めなくすること。
- クライアント演出とサーバー確定結果を乖離させること。
- スキップ不能な長時間カットインを連続させること。

## 6. 改修の優先順位

ホームはUIとして約90%、キャラクターページは約70〜80%の到達度を前提とする。両画面も全画面監査と統一改修の対象に含める。全体の共通基盤、情報設計、演出方針と不整合が判明した場合は、既存到達度にかかわらず必要な構造・デザイン・演出を改修する。

タイトル、認証、チュートリアルは、他画面の体験・導線・演出の基準が確定してから最後に統合する。初回体験だけを先に作り込まない。

### フェーズA: 全画面監査と共通基盤

- 全画面を「機能」「情報設計」「デザイン」「演出」「空状態・失敗状態」「モバイル操作」「性能」の7観点で監査する。
- カラー、文字、余白、ボタン、状態、モーダル、ローディング、トーストを共通トークン化する。
- 画面共通の視覚状態（通常、押下、無効、処理中、成功、警告、失敗）を統一する。

### フェーズB: 未完成の主ゲームループ

- クエスト／派遣、マップ、バトル準備、戦闘再生、リザルトを完成させる。
- 戦闘は、通常攻撃、スキル、固有スキル、決定イベント、リザルトの5層で演出を実装する。
- 仕様どおりの報酬、消費、再挑戦、編成戻り、再開処理、通信失敗時の導線を揃える。

### フェーズC: 抗争・対人・協力ループ

- PvP、GvG、レイド、ギルドを完成させる。
- 開催前、マッチング中、開催中、結果、非参加、権限不足の各状態を設計する。
- 「今の戦況」「自分の貢献」「組織への次の行動」を最上位に表示する。

### フェーズD: 成長・収集・経済ループ

- ガチャ、獲得結果、ショップ、バッグ、ミッション、プレゼント、ランキングを完成させる。
- 育成・獲得・交換・受取の成功体験を短く明快にし、高レアのみ強い演出予算を使う。
- Stripe依存の決済確定処理は別途扱い、決済以外の画面体験・状態表示・導線は先行して完成させる。

### フェーズE: ソーシャル・補助画面

- チャット、BBS、フレンド、設定、メニュー、通知／受信箱、法務画面を完成させる。
- 投稿なし、友達なし、権限不足、読み込み中、通信失敗などの空状態を必ず実装する。

### フェーズF: ホーム・キャラクターの統一改修

- ホームは放置報酬、開催中抗争、立ち絵、背景、通知の演出密度と、全画面共通の情報階層・操作状態を統一する。
- キャラクターページは立ち絵レイヤー、装備・スキルのレアリティ表現、成長結果のフィードバックと、編成・戦闘準備との導線を統一する。
- 監査で不整合が確認された場合は、既存の情報構造も含めて改修する。

### フェーズG: 初回体験とリリース判定

- タイトル、認証、チュートリアルを、完成した本編UI・演出・文言に合わせて統合する。
- 主要画面をモバイル幅とPC幅で撮影し、ベンチマーク原則に対して監査する。
- 空状態、処理中、通信失敗、報酬獲得、戦闘結果、長文・多桁数値を確認する。
- 主要操作をE2Eとスクリーンショット比較で回帰確認する。

## 7. 画面監査の必須項目

各画面について、以下を一つの監査表で管理する。

| 観点 | 確認内容 |
| --- | --- |
| 機能 | 正常系、入力制約、二重送信防止、権限、サーバー確定値との一致 |
| 情報設計 | 主目的、結果、次の行動が一目で分かるか |
| デザイン | 世界観、文字階層、余白、コントラスト、縦画面での視線誘導 |
| 演出 | 押下、読み込み、成功、失敗、報酬、重要イベントのフィードバック |
| 状態 | 初回、空、処理中、通信失敗、権限不足、上限到達、完了後 |
| 操作 | 片手操作、タップ領域、スクロール、モーダル閉鎖、誤操作防止 |
| 性能 | 初期描画、画面遷移、画像読み込み、連打時、長時間表示 |

## 8. 各フェーズの完了条件

- 各画面に主目的、結果、次の行動が一つずつ明確に存在する。
- 主要な操作対象は片手で押しやすく、処理中と無効状態を識別できる。
- 高負荷の演出はスキップまたは短縮でき、通常プレイを妨げない。
- サーバー確定値と画面表示が一致する。
- 画面遷移、空状態、失敗状態を含むスクリーンショット確認が完了している。
