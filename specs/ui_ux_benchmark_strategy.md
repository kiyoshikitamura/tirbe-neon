# UI / UX・演出ベンチマーク戦略

更新日: 2026-08-07

本書はベンチマークから採用する体験原則と監査観点を扱う。共通UIの具体的な色、文字、ボタン、カード、モーダル、ローディング、キャッシュ、信頼境界は`ui_design_system.md`を正本とする。

## 1. 目的

TRIBE NEONは、かつてブラウザソーシャルゲームのGvGに熱中したプレイヤーが、現在の生活リズムでも短時間に「所属」「抗争」「成長」を楽しめる縦画面ブラウザゲームを目指す。

UI改修は単なる見栄えの改善ではなく、以下を同時に満たすことを目的とする。

- 抗争に参加して組織へ貢献する高揚感を伝える。
- 忙しい日でも短時間で放置報酬、育成、編成、1戦を完了できる。
- 30代半ばから40代半ばの男女が、情報を無理なく読み取り片手で操作できる。
- 現代アウトロー、格闘技、ヤンキー、極道、夜の世界という題材を、固有のネオン表現で再解釈する。

## 2. 想定ユーザー

- 30代半ばから40代半ばの男女。
- アウトロー、格闘技、ヤンキー、極道、夜の世界を好む。
- 15年前から20年前のブラウザソーシャルゲームで、ギルド戦・GvG・ランキング競争を経験した。
- 成長、収集、組織への貢献は好むが、長時間の拘束は避けたい。

## 3. ベンチマーク・マトリクス

| 領域 | 主ベンチマーク | 参照する原則 |
| --- | --- | --- |
| GvG・ギルド抗争 | ギャングロードジョーカー、戦国炎舞、任侠伝、拳極 | 所属感、開催時間の緊張、個人貢献、勢力順位、仲間と共有する戦況 |
| 格闘・対決の熱量 | 刃牙 THE STRONGEST PROOF、拳極、喧嘩道、クローズ×WORST | 一撃の重さ、対決前の緊張、勝敗の重さ、太い漢字、荒々しい衝撃表現 |
| 必殺技・獲得演出 | ドラゴンボールZ ドッカンバトル、刃牙 THE STRONGEST PROOF | 溜め、決め、余韻の三段構成。高レアだけを強く見せる緩急 |
| 放置・育成・日課 | 放置少女 | 短時間の報酬受取、成長確認、編成、収集への導線 |
| 縦画面可読性 | Pokémon TCG Pocket、Marvel Snap | 片手操作、明快な状態表現、短い解決演出。主題材ではなく補助参照 |

ベンチマークは体験原則の参照に限定する。固有のアート、キャラクター、文言、画面構成、効果素材を複製しない。

## 4. 共通ビジュアル方針

世界観、情報階層、文字、色、状態表現は`ui_design_system.md`に統合した。本書では、各ベンチマークから採用する体験の強度と評価軸だけを扱う。

## 5. バトル演出方針

サーバー確定の再生結果を正本とし、演出は結果を分かりやすく気持ちよく伝えるために使う。

| 層 | 目安 | 表現 |
| --- | --- | --- |
| 通常攻撃 | 0.3〜0.5秒 | 前進、攻撃線、命中フラッシュ、ダメージ数値 |
| 通常スキル | 0.6〜0.9秒 | 属性色、短いスキル名、対象表示、状態異常アイコン |
| 固有・高レアスキル | 1.2〜1.8秒 | 一瞬の暗転、立ち絵カットイン、固有色、専用SE、強い命中演出 |
| 決定イベント | 0.5〜1.0秒 | 撃破、ブレイク、クリティカル、回復、フェーズ移行、GvG陥落 |
| リザルト | 即時表示 | 勝敗、総ダメージ、最大ダメージ、キャラ別貢献、報酬。詳細ログは任意展開 |

避けること:

- 全スキルで全画面演出を行うこと。
- 演出中にHP、残り時間、勝敗条件を読めなくすること。
- クライアント演出とサーバー確定結果を乖離させること。
- スキップ不能な長時間カットインを連続させること。

## 6. 改修の優先順位

ホームはUIとして約90%、キャラクターページは約70〜80%の到達度を前提とする。両画面も全画面監査と統一改修の対象に含める。全体の共通基盤、情報設計、演出方針と不整合が判明した場合は、既存到達度にかかわらず必要な構造・デザイン・演出を改修する。

タイトル、認証、チュートリアルは、他画面の体験・導線・演出の基準が確定してから最後に統合する。初回体験だけを先に作り込まない。

工程の正本は`ui_design_system.md`第12章とする。順序は次のとおり。

1. UI仕様統合と共通基盤
2. バトル中を除く全対象画面のUI
3. マスタデータ作成
4. 不足画像生成
5. バトル中画面
6. 本番データ・本番画像によるUI最終調整
7. タイトル、認証、チュートリアル

全工程を通じ、各画面を「機能」「情報設計」「デザイン」「演出」「状態」「操作」「性能」の7観点で監査する。

## 7. 画面監査の必須項目

各画面について、以下を一つの監査表で管理する。

| 観点 | 確認内容 |
| --- | --- |
| 機能 | 正常系、入力制約、二重送信防止、権限、サーバー確定値との一致 |
| 情報設計 | 主目的、結果、次の行動が一目で分かるか |
| デザイン | 世界観、文字階層、余白、コントラスト、縦画面での視線誘導 |
| 演出 | 押下、読み込み、成功、失敗、報酬、重要イベントのフィードバック |
| 状態 | 初回、空、処理中、通信失敗、権限不足、上限到達、完了後 |
| 操作 | 片手操作、タップ領域、スクロール、モーダル閉鎖、誤操作防止 |
| 性能 | 初期描画、画面遷移、画像読み込み、連打時、長時間表示 |

## 8. 各フェーズの完了条件

- 各画面に主目的、結果、次の行動が一つずつ明確に存在する。
- 主要な操作対象は片手で押しやすく、処理中と無効状態を識別できる。
- 高負荷の演出はスキップまたは短縮でき、通常プレイを妨げない。
- サーバー確定値と画面表示が一致する。
- 画面遷移、空状態、失敗状態を含むスクリーンショット確認が完了している。
