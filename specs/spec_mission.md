# システム仕様書：ミッション機能 (Mission System)

プレイヤーに短期・長期の目標を提供し、定着化およびキャラクター育成・ゲーム内コンテンツ参加を促すミッションシステムの仕様書です。

---

## 1. 機能概要

本システムは、特定の課題をクリアすることでゲーム内報酬（アイテム、トークン等）を獲得できる機能です。
ミッションは **「デイリーミッション」** と **「通常ミッション（アチーブメント）」** の2種類に大別され、将来の拡張を容易にするためマスタデータ駆動型で設計されます。

---

## 2. UI / UX 仕様 (画面フロー ＆ 表示)

### ① マイページ (ホーム画面) のバッジ導線
- マイページに配置された「ミッション」ボタンには、クリア状態（未受け取り）のミッションが1件以上ある場合、ボタンの右上に赤丸の通知バッジを表示します。
- バッジには未受取のミッション件数を動的に数値表示します（例: `🔴 3`）。

### ② 画面遷移 ＆ ローディング制御（スケルトンスクリーン）
- **遷移時の動作**:
  1. ユーザーが「ミッション」ボタンをタップ。
  2. クライアントは画面遷移を行い、即座に「ミッション画面のヘッダー・タブ」および「リスト枠のプレースホルダー（スケルトン行）」を描画します。
  3. バックグラウンドでAPI通信 (`GET /api/missions`) を行い、読み込み完了次第、スケルトン表示をフェードアウトさせて実データ（進捗状況）を表示します。
  4. ホーム画面からの遷移時、バックグラウンドでの事前ロード（プリフェッチ）が既に完了している場合は、ローディングをスキップして即時にリストを表示します。

```

└──────────────────────────────────────────────┘
```

### ③ ミッション一覧画面のレイアウト
- **上部**: タブメニュー（「デイリー」「通常」）、および「一括受け取り」ボタン。
- **ミッションカード（各項目）の構成**:
  - **タイトル ＆ 説明文**: 例「ルイのレベルアップ / ルイのレベルを10にする」
  - **進捗バー (Progress Bar)**: `[ 現在値 / 目標値 ]` の視覚的表示（パーセンテージ）。
  - **クリア報酬**: 報酬アイテムのアイコン画像と個数（例: `[コインアイコン] x1000`）。
  - **アクションボタン**:
    - `未達成`: グレーアウトした「進行中」ボタン。押下不可（または関連画面へのショートカット遷移）。
    - `クリア（未受取）`: 明るく点滅する「受け取る」ボタン。タップすると、そのアイテムのみを回収。
    - `受取済み`: 「受取済み」のテキスト表示（またはカード自体が半透明化）。

## 3. 拡張可能な課題構造 (Trigger & Evaluation)

将来的に新たなゲーム機能が追加された際、マスタデータの更新のみで「〜をクリアする」という課題を追加・検知できる **「パラメータ駆動型トリガー評価モデル」** を導入します。

### ① トリガーイベントのディスパッチ
ゲーム内の特定の進捗変更やアクション時に、イベントディスパッチャーを介して共通のイベントオブジェクトを発行します。

```json
// 発行されるイベントオブジェクトの例
{
  "event_type": "CHAR_LEVEL_UP",
  "user_id": "usr_98273",
  "params": {
    "character_id": "rui",
    "new_level": 20
  }
}
```

### ② マスタデータとパラメータの評価
ミッションマスタは、`trigger_type` に加え、JSON形式の `condition_params` カラムを持ちます。
ミッション制御コアは、イベントパラメータとマスタの条件パラメータを動的に比較評価し、合致する場合のみ進捗を加算します。

#### ミッション課題マスタ設定例:
| mission_id | title | trigger_type | target_value | condition_params (評価条件JSON) |
| :--- | :--- | :--- | :--- | :--- |
| `daily_login` | ログインしよう | `DAILY_LOGIN` | 1 | `null` |
| `level_rui_20` | ルイを鍛え上げよ | `CHAR_LEVEL_UP` | 20 | `{"character_id": "rui"}` |
| `level_user_10` | 半グレの首領への道 I | `USER_LEVEL_UP` | 10 | `null` |
| `pvp_win_5` | PvPで強者を示せ | `PVP_WIN` | 5 | `null` |
| `expedition_hard_3` | 全面抗争を生き残れ | `EXPEDITION_CLEAR` | 3 | `{"course_type": "HARD"}` |
| `daily_expedition_1` | 本日のシノギ完了 | `EXPEDITION_CLEAR` | 1 | `null` |
| `m_invite_01` | 盟友の招聘 I | `USER_INVITE` | 1 | `null` |

## 4. 各種ミッションの仕様

### ① デイリーミッション
- **リセット時間**: 毎日 **午前4:00 (JST)**。
- **自動クリア・進捗リセット**:
  - 午前4:00を跨いだタイミングで、前日分のデイリーミッション進捗はすべてリセットされ、当日の新規ミッションが自動割り当てられます。
  - **未受取報酬の救済仕様**: クリアした状態で報酬を受け取らずに午前4:00を跨いだ場合、未受取の報酬は自動的に **「プレゼントボックス（受取期限24時間）」へ自動転送** されます（プレイヤーの努力損失を防止）。

### ② 通常ミッション (累積アチーブメント)
- **リセット**: なし。恒常的に累積されます。
- **多段階（ステップ）構成**:
  - 「PvPで10勝する」「PvPで50勝する」「PvPで100勝する」のように、1つの系統が段階的に開放される仕様。前段階をクリアし、報酬を受け取ると次のステップのミッションが自動的に有効化されます。

### ③ 招待ミッション (ユーザー招待報酬)
- **リセット**: なし。通常ミッションと同様に恒常的に累積されます。
- **目標人数**: 最大 10名。1人招待するごとに招待元のミッション進捗が `+1` され、最大10人目までそれぞれ1名ずつ報酬（ダイヤ等）が受け取れます（`m_invite_01`〜`m_invite_10`）。
- **招待人数の上限**: 各ギフトコードは 10名までしか使用できません。11人目以降が入力しようとすると「このギフトコードは10人使用済です」のエラーを返します。
- **被招待者側の報酬**: ギフトコードを入力してゲームを開始した被招待者には、プレゼントBOX（`presents` テーブル）へ入力報酬（ダイヤ +100）が即時付与されます。

## 5. API ＆ データフロー

### ① ミッション一覧取得 (`GET /api/missions`)
プレイヤーの現在のミッション進行状況およびマスタデータを取得します。

- **Request**:
  - Header: `Authorization: Bearer <token>`
- **Response (JSON)**:
  ```json
  {
    "missions": [
      {
        "mission_id": "level_rui_20",
        "category": "daily",
        "title": "ルイを鍛え上げよ",
        "description": "ルイのレベルを20にする",
        "current_progress": 15,
        "target_value": 20,
        "status": "progress",
        "reward": {
          "item_id": "coin",
          "quantity": 500
        }
      },
      {
        "mission_id": "daily_login",
        "category": "daily",
        "title": "デイリーログイン",
        "description": "ゲームにログインする",
        "current_progress": 1,
        "target_value": 1,
        "status": "clear",
        "reward": {
          "item_id": "gacha_ticket",
          "quantity": 1
        }
      }
    ]
  }
  ```

### ② 報酬受け取り・一括受け取り (`POST /api/missions/claim`)
ミッションの報酬を請求します。一括回収時は、配列でIDを送信します。

- **Request (JSON)**:
  ```json
  {
    "mission_ids": ["daily_login"]
  }
  ```
- **データ処理プロセス (サーバーサイド)**:
  1. 対象ミッションが本当に `status = 'clear'` かつ `CLAIMED` 未処理か検証。
  2. トランザクションを開始。
  3. 対象ミッションのステータスを `claimed` に更新。
  4. 報酬アイテムを **プレゼントボックス（`presents` テーブル）へインサート**。
  5. トランザクションをコミット。
- **Response (JSON)**:
  ```json
  {
    "success": true,
    "claimed_mission_ids": ["daily_login"],
    "sent_to_presents": [
      {
        "item_id": "gacha_ticket",
        "quantity": 1,
        "present_id": 10293
      }
    ]
  }
  ```
