# システム仕様書：プレゼントボックス ＆ お知らせ機能

プレイヤーに対してアイテムを安全に配布・管理する「プレゼントボックス」と、イベントやメンテナンス情報を遅滞なく伝達する「お知らせ機能」の仕様書です。
本機能は、画面遷移時のローディングストレスを排除するゼロレイテンシ（都度ロードなし）設計を基本とします。

---

## 1. データキャッシュ ＆ ロード戦略 (ゼロレイテンシ設計)

ユーザーが画面を開くたびに「Now Loading...」による操作ロック（グレーアウト）が発生するのを防ぐため、以下のデータロード戦略を適用します。

### ① アプリ起動（ログイン時）の一括プリフェッチ
- アプリケーションが起動し、マイページ（ホーム）の描画を開始する段階で、バックグラウンドにて以下のデータを一括取得（プリフェッチ）し、クライアント側のグローバルステート（Redux, Pinia等）にキャッシュします。
  - **プレゼントボックスの未受取一覧（件数、および直近データ）**
  - **お知らせのアクティブな一覧（ID、タイトル、掲載期間、重要度等）**
  - **お知らせの既読情報リスト**

### ② キャッシュ優先レンダリング (Stale-While-Revalidate: SWR)
- ユーザーがマイページから「プレゼントボックス」または「お知らせ」を開いた際、**ローディング画面（スピナー）を表示せず、即座にキャッシュデータを表示（レンダリング時間 0秒）** します。
- 画面表示と並行して、バックグラウンドで差分取得APIをリクエストします。
- サーバーデータに新しいアイテムやお知らせが追加されていた場合のみ、UIリストをなめらかにフェードインで追加更新し、プレイヤーの閲覧操作を一切妨げません。

---

## 2. プレゼントボックス仕様 (Present Box)

### ① UI / UX 仕様 (画面フロー ＆ 操作)
- **マイページバッジ**: 
  - 未受取のプレゼントがある場合、プレゼントアイコンの右上にバッジを表示（例: `🔴` または未受取件数）。
- **プレゼント一覧**:
  - タブメニュー（「未受取」「受取履歴」）。
  - 送付日時、件名（例: 「デイリーミッションクリア報酬」）、アイテム名、個数、**受取期限のカウントダウン**（例: `あと3日` または `あと12時間`）を表示。
- **一括受け取り ＆ 個別受け取り**:
  - 画面上部に「一括受け取り」ボタンを配置。
- **ノンブロッキング操作 (楽観的UI更新)**:
  - 「受け取る」ボタンまたは「一括受け取り」ボタンを押した際、**画面全体を操作不能にするグレーアウトロックは行いません**。
  - タップされたボタン自体、または対象アイテムカードの端に小さなスピナー（インジケータ）を表示し、通信中もスクロールや戻るボタン等の他の操作を可能にします。
  - サーバーの処理が完了した段階で、対象アイテムカードがスライドアウトして消滅します。

### ② 期限切れアイテムの自動消滅
- 各プレゼントには `expire_at`（受取期限）が設定されます。期限を過ぎたアイテムはサーバー側バッチ処理、またはAPIリクエスト時のフィルタリングによって自動的に消滅（削除）します。

## 3. お知らせ機能仕様 (News & Notification)

### ① UI / UX 仕様 (画面フロー ＆ 表示)
- **お知らせバッジ**:
  - 未読の「重要お知らせ」または「新着お知らせ（掲載開始から24時間以内）」がある場合、お知らせボタンに赤丸バッジを表示します。
- **お知らせ一覧画面**:
  - 「重要」「イベント」「アップデート」のタブ切り替え。
  - 各項目にはタイトル、掲載開始日時、および未読・既読状態（未読の場合はタイトルの左に `NEW` バッジ）を表示。
- **お知らせ詳細ポップアップ**:
  - タイトルをタップすると、リッチテキスト（HTML/Markdown）で記述されたお知らせ詳細がポップアップ、または全画面で瞬時に表示されます（詳細テキストもプリフェッチ済みのためロード時間は発生しません）。
- **ログイン時強制ポップアップ**:
  - 重要度 `IMPORTANT` で指定されたお知らせで、ユーザーがまだ「一度も閉じていない（既読にしていない）」ものは、ゲームログイン時に強制的に画面中央にポップアップ表示し、確認を促します。

## 4. API ＆ シーケンス仕様

### ① 起動時プリフェッチAPI (`GET /api/bootstrap/sync`)
ゲーム起動時にホーム画面ローディングの裏で叩く、一括データ取得API。

- **Response (JSON)**:
  ```json
  {
    "present_summary": {
      "unclaimed_count": 5,
      "presents": [
        {
          "present_id": 10293,
          "item_id": "coin",
          "quantity": 1000,
          "message": "デイリーミッション報酬",
          "expire_at": "2026-07-20T04:00:00Z"
        }
      ]
    },
    "news_summary": {
      "unread_count": 2,
      "news_list": [
        {
          "news_id": 501,
          "category": "important",
          "title": "[重要] 7月15日 メンテナンスのお知らせ",
          "start_at": "2026-07-13T00:00:00Z",
          "end_at": "2026-07-16T00:00:00Z"
        }
      ]
    }
  }
  ```

### ② プレゼント受け取りAPI (`POST /api/presents/claim`)
指定したIDのプレゼントを受け取り、所持枠へ反映させます。

- **Request (JSON)**:
  ```json
  {
    "present_ids": [10293] -- 一括受け取りの場合は複数IDを送信
  }
  ```
- **データ処理プロセス (サーバーサイド)**:
  1. トランザクション開始。
  2. 対象IDの status が `unclaimed` かつ有効期限内かチェック。
  3. `presents` の status を `claimed` に更新、`claimed_at` を現在時刻に更新。
  4. ユーザーの所持金（`users.coins` 等）や所持品（`user_items`）テーブルに加算。
  5. トランザクションコミット。
- **Response (JSON)**:
  ```json
  {
    "success": true,
    "claimed_present_ids": [10293],
    "added_items": [
      {
        "item_id": "coin",
        "quantity": 1000
      }
    ]
  }
  ```

### ③ お知らせ既読化API (`POST /api/news/read`)
お知らせを読んだ（または強制ポップアップを閉じた）タイミングで既読フラグをサーバーへ送信します。

- **Request (JSON)**:
  ```json
  {
    "news_id": 501
  }
  ```
- **Response (JSON)**:
  ```json
  {
    "success": true,
    "news_id": 501,
    "read_at": "2026-07-13T08:25:00Z"
  }
  ```
