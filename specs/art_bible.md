## 0. 本書の目的

本書は、TRIBE NEONにおけるキャラクター、背景、装備、アイテム、スキル、演出、広告クリエイティブを横断し、今後追加されるアセットが同一作品として認識できるためのアート判断基準を定義する。

本書はゲームルールや共通UI仕様を上書きしない。既存仕様と矛盾する場合は、以下の責務分担を優先する。

- ゲームルール・DB・画面固有機能: `game_spec.md` および各 `spec_*.md`
- 共通UI、色値、文字、ボタン、カード、モーダル、レイアウト: `ui_design_system.md`
- マイページ固有の情報・導線: `mypage_design_policy.md`
- キャラクター個別設定: `assets_characters.md`
- 既存生成プロンプトの個別指定: `visual_prompt_sheet.md`
- 本書: 作品全体の視覚的一貫性、制作判断、追加アセットの受入基準

既存の `visual_concept.md` に記載された確定済みアート方針は本書へ継承した。v1.1以降、`visual_concept.md`は旧来の詳細資料として維持し、矛盾する場合は本書を優先する。

## 1. Brand Core

### 1.1 作品の視覚的定義

TRIBE NEONは、現代東京圏の夜の歓楽街・ストリート・裏社会を舞台とする、セミリアル2Dアニメのストリート／アウトロー作品である。

視覚的な主語は「ネオンそのもの」ではなく、夜の都市で生きる人物と、その人物が属する街・集団・文化である。

### 1.2 Core Keywords

- 現代東京圏の夜
- 歓楽街、雑居ビル、路地、交差点、港湾、都市道路
- ストリート、クラブ、夜職、ヒップホップ、現代アウトロー
- マットブラック、チャコール、鉄、革、ナイロン、ガラス、濡れた路面
- 看板や店舗照明から受ける環境光
- 清潔な2D線画と立体感のある陰影
- 大人が格好良いと思える現代性

### 1.3 TRIBE NEONではないもの

以下は原則として採用しない。

- サイバーパンク、未来都市、SF都市
- ホログラム、未来HUD、レーザー主体の世界
- 武器・服・建物そのものが常時ネオン発光する表現
- 昭和〜平成初期のヤンキー文化の単純再現
- 過度な軍事・サバイバル作品化
- 完全写実、写真、3Dレンダリング調
- ファンタジー装備・魔法世界への逸脱

## 2. Color / Light Philosophy

### 2.1 基調

アートの基調は以下とする。

- マットブラック
- チャコール
- つや消し銀
- くすんだ金
- 深い赤

シアン、マゼンタ、紫、青はアクセントとして使用できるが、自発光する未来素材ではなく、看板、店舗、車両、街灯など現実に存在可能な光源からの環境反射として扱う。

### 2.2 光の原則

- 人物や物体は都市の光を受ける。
- 画面全体を均一なネオンカラーで染めない。
- 暗部を残し、夜らしいコントラストを維持する。
- 最高レア、重要報酬、勝敗、抗争開始など、意味のある瞬間のみ光量を上げる。

## 3. Environment / Location Bible

### 3.1 背景アセットの扱い

現在の7拠点背景を既存ビジュアル基準として維持する。背景正本の格納先は `public/bg/` とする。

確認済み既存アセット:

- `bg_street_shinjuku.png`
- `bg_street_shibuya.png`
- `bg_street_ikebukuro.png`
- `bg_street_roppongi.png`
- `bg_street_akihabara.png`
- `bg_street_kawasaki.png`
- `bg_street_yokohama.png`

既存画像をArt Bibleへ合わせるために一律再生成しない。今後の追加背景・イベント差分・広告背景は、既存7背景と本章の双方へ整合させる。

### 3.2 全拠点共通ルール

- 現代日本の都市として成立すること。
- 基本時間帯は夜。
- キャラクター立ち絵を置いた際、顔・輪郭・衣装が背景へ埋没しないこと。
- UI予定領域へ高密度な看板・文字・強い光源を集中させないこと。
- 濡れた路面やガラス反射は使用可能だが、全面鏡面化しないこと。
- 実在企業ロゴを使用しないこと。
- 生成AI由来の意味不明な文字を主役にしないこと。
- 同一拠点の追加背景では、色だけでなく建築・道路・店舗・文化的モチーフでも拠点を識別可能にする。

### 3.3 7拠点 Visual Identity

以下をv1.1確定仕様とする。既存7背景を維持しつつ、今後の追加背景、イベント差分、キャラクター文化圏、広告背景を統一するための基準として使用する。

#### 新宿

役割: 高密度歓楽街 / TRIBE NEONの都市夜景を象徴する基準拠点。

- 雑居ビル、飲食・夜業態の看板、狭い都市道路
- 赤、暖色、白を含む密度の高い人工光
- 人の気配と夜の緊張感
- 高級すぎず、荒廃しすぎない

#### 渋谷

役割: ストリート / ファッション / クラブカルチャー。

- 交差点、坂、都市広告、若いナイトカルチャー
- 新宿より開けた都市空間
- ファッション、音楽、ストリートの速度感
- サイバーパンク都市へ寄せない

#### 池袋

役割: 雑多な繁華街 / 表通りと裏路地の落差。

- 商業ビル、飲食街、路地
- 都市生活感と雑多さ
- 新宿との差は「歓楽街の圧」より生活圏との混在で出す

#### 六本木

役割: 富裕層 / クラブ / 夜の成功者。

- ガラス、石材、黒、金属、高級車が似合う都市空間
- 他拠点より整理された光と建築
- ゴールドや暖色は高級感として使用
- SF的ラグジュアリーにはしない

#### 秋葉原

役割: 電気街 / サブカルチャー / 高密度情報都市。

- 電子看板、店舗、縦方向の情報密度
- 青・シアン系照明を比較的使用しやすい
- ただし未来都市・ホログラム・電脳空間にはしない
- 現実の電気街として成立させる

#### 川崎

役割: 工業 / ヒップホップ / ハードストリート。

- コンクリート、鉄、高架、道路、工業的構造物
- 他拠点より無骨で低彩度
- ストリート、ラップ、車両文化との親和性
- 軍事基地・終末世界にはしない

#### 横浜

役割: 港 / 都市夜景 / 開放感。

- 港湾道路、水面、倉庫、都市光
- 水面・ガラスへの反射
- 7拠点の中では比較的広い空と奥行きを許容
- 観光ポスター的な爽やかさではなく、夜のストリート作品として維持する

## 4. Character Art Direction

### 4.1 基本画風

- 2Dセミリアル・ストリートアニメスタイル
- 完全な全身立ち絵を基本とする
- 頭頂から靴先まで画面内へ収める
- 細くクリーンな輪郭線
- 顔、髪、瞳、衣服、アクセサリーへ繊細な陰影
- 写実・3Dへ寄せない
- 線画はアニメ的に整理しつつ、素材と人体の立体感は十分に残す
- キャラクター単体で「現代日本の人物」と認識できる服飾・小物・身体表現を優先する

### 4.2 参照モデル

既存本番キャラクターを、今後の追加制作における参照モデルとする。

特に `assets_characters.md` で実物画像から逆算済みのレイジ、ルイは、以下の対照的な基準として扱う。

#### レイジ系参照
- 成人男性の都会的アウトロー
- 金髪、ジャケット、デニム、チェーン、高級時計、タトゥー
- 威圧一辺倒ではなく、自信・余裕・社会的成功を感じる表情
- 黒系衣装の中に金属・肌・髪の明暗差を作り、全身の情報を潰さない

#### ルイ系参照
- 成人女性の地雷系／量産型ガーリー
- 黒白を基礎とした衣装でも、髪、肌、リボン、レースの質感差を明確にする
- 「可愛い」だけでなく、アンニュイ、不安定さ、夜の空気を表情で持たせる
- 露出や性的強調を主目的とせず、ファッションと感情でキャラクター性を作る

これらは全キャラクターを同型へ寄せるためではなく、TRIBE NEON内で許容される表現幅の両端を示す参照モデルである。

### 4.3 キャラクターが表現する文化

キャラクターは単なる「不良」ではなく、現代の都市ナイトカルチャーに存在し得る人物として設計する。

使用可能な方向性:

- ストリート
- ヒップホップ
- 夜職
- 地雷系 / 量産型ガーリー
- 格闘技
- 富裕層 / IT・経営者
- 現代アウトロー
- クラブカルチャー
- バー、ライブハウス、ダンス、DJ、ラップ等の夜間カルチャー

タトゥー、ピアス、時計、チェーン、服飾は人物の社会性・所属・価値観を示す記号として使う。

### 4.4 年齢・体型・顔

- 基本的に成人として認識できる年齢感を持たせる
- 童顔・若年寄りのデザインでも、服装・体格・メイク・表情で成人として成立させる
- 男性は細身、標準、筋肉質、重量級まで許容する
- 女性は華奢、標準、モデル体型、グラマラスまで許容するが、全員同一体型へ寄せない
- 顔の輪郭、目、眉、鼻、口、年齢感に個体差を持たせる
- 「美男美女だけの同一顔量産」を避ける
- 傷、タトゥー、髭、メイク、肌質などを人物履歴の情報として使用できる

### 4.5 シルエットと構図

- 一覧表示でも人物を識別できるシルエットを持たせる
- 髪型、肩幅、アウター、パンツ／スカート、靴、アクセサリーの組合せで差を作る
- 同一用途の全身立ち絵は頭頂、目線、足元位置、全身占有率を統一する
- 手や腕を完全に胴体へ密着させず、人物シルエットが読める余白を確保する
- ポーズは人物性を表現するが、過度なアクションポーズでUI利用性を損なわない
- 武器や大型小物がある場合も、顔と体幹の識別を妨げない

### 4.6 衣装・素材

衣装は「現代に実在可能」を基本条件とする。

推奨素材:
- レザー
- デニム
- ナイロン
- コットン
- スーツ地
- サテン
- レース
- 金属アクセサリー
- スニーカー、革靴、ブーツ

禁止または慎重使用:
- 発光布
- ホログラム素材
- SFアーマー
- ファンタジー鎧
- 世界観上の理由がない軍用フル装備

高価さは発光や宝石量ではなく、仕立て、素材、時計、アクセサリー、シルエットで表現する。

### 4.7 タトゥー・傷・アクセサリー

- タトゥーは現代アウトロー文化の一部として許容する
- 和彫り、トライバル、ブラックワーク、ワンポイント等を人物設定に合わせて使い分ける
- 全員にタトゥーを付与しない
- 傷は顔の特徴として強い識別力を持つため、主要人物以外で乱用しない
- 時計、チェーン、ピアス、リングは富裕度・職業・文化圏の表現に使用する
- 実在ブランドロゴは避ける

### 4.8 色設計

- キャラクター固有色は持たせてよいが、全身を単一色で塗り潰さない
- 黒系衣装が多い世界観のため、素材差、肌、髪、アクセサリー、環境光で分離する
- 背景にシアンやマゼンタがある場合、キャラクター本体も同色で全面発光させない
- 高レアリティだからといって本体彩度を不自然に上げない
- レアリティ差は描き込み密度、素材感、ポーズ、演出、UIフレームとの組合せで表現する

### 4.9 個別キャラクター

主要キャラクターの顔、髪、衣装、タトゥー、アクセサリー、ポーズは `assets_characters.md` を正本とし、本書の一般論を理由に変更しない。

個別仕様と本書が衝突する場合:
1. キャラクター個別設定を優先
2. その表現がTRIBE NEON全体へ拡張可能かを確認
3. 必要ならArt Bible側へ例外として追記する

### 4.10 キャラクター生成テンプレート

追加キャラクター生成時の入力は、最低限以下を明示する。

- 年齢帯
- 性別表現
- 体格
- 顔立ち
- 髪型・髪色
- 表情
- 職業／文化圏
- 上半身衣装
- 下半身衣装
- 靴
- アクセサリー
- タトゥー／傷の有無
- ポーズ
- 固有色
- 全身立ち絵
- 単色背景
- Negative Prompt

共通ベース方向:
`vivid 2D anime style, semi-realistic anime look, detailed facial features, realistic soft textures, clean sharp linework, modern Japanese street and nightlife fashion, full body standing portrait, head-to-toe, contemporary urban outlaw aesthetic`

共通除外方向:
`photorealistic, 3d render, childlike proportions, fantasy armor, medieval, cyberpunk, cyborg, hologram, futuristic sci-fi, excessive neon glow, cropped legs, cropped feet, deformed hands, extra fingers, unreadable prominent text, watermark`

### 4.11 キャラクターAsset QA

透過前原画:
- 単色背景と人物輪郭の色差が十分にある
- 髪先、指、アクセサリー周辺が背景色と近すぎない
- 足先、髪先、衣装端がキャンバス外へ切れていない
- 手指・顔・タトゥー・アクセサリーに生成破綻がない

透過後:
- 髪の毛周辺にグリーンフリンジが残っていない
- 半透明素材や細いアクセサリーが欠損していない
- 指・髪先・服のフリルの輪郭が過度に削れていない
- 足元に不要な影や背景色が残っていない
- 本番背景上で白縁・黒縁・色残りが目立たない

ゲーム内表示:
- マイページで顔がUIに隠れない
- キャラクターページで全身表示した際に頭頂・足元が切れない
- 既存キャラと並べた際に縮尺が不自然でない
- 背景と同化して輪郭が消えない
- スマートフォン実寸で顔と主要アクセサリーを認識できる

## 5. Equipment / Item / Skill

本番画像の格納先は以下を正とする。

- 装備: `public/equipments/`
- スキル: `public/skills/`

GitHubのコード検索は画像ファイル一覧を十分に返さないため、個別画像の視覚監査はファイル名を特定できたものから実施する。本章の制作規則は既存 `visual_concept.md` とゲーム仕様を基礎とする。

### 5.1 Equipment Core

装備は「現代の都市で実在可能、または実在品を少し誇張したもの」を基本とする。

- ストリート、ファッション、格闘、夜職、現代アウトローの文化圏に接続する
- 素材感とシルエットを優先する
- 小サイズでも装備カテゴリを識別できる
- SF武器、魔法武器、ファンタジー鎧へ寄せない
- 発光そのもので強さを表現しない
- 実在ブランドロゴは使用しない

### 5.2 Equipment Category Direction

装備スロットの正式なゲーム仕様は各装備仕様を優先する。アート上は、少なくとも以下の視覚カテゴリを識別可能にする。

- 武器／攻撃系: バット、ナイフ以外の合法・世界観上適切な格闘小物、グローブ等を含む現代的な戦闘モチーフ
- アウター／防具系: ジャケット、レザー、ナイロン、プロテクター等
- 足元: スニーカー、ブーツ、革靴
- アクセサリー: チェーン、時計、リング、ブレスレット等
- 専用装備: 対象キャラクターの文化・色・象徴を通常装備より強く反映する

※具体的な装備種別・7箇所等のゲームルールはArt Bibleでは決めず、ゲーム仕様を正とする。

### 5.3 Rarity Direction

レアリティは「色違い」だけで作らない。

低レア:
- シンプルな素材
- 少ない装飾
- 読みやすい単純シルエット

高レア:
- 素材の質感向上
- ディテール増加
- 特徴的な形状・加工
- 高級感、希少感
- UI側の `RarityFrame` と連動した演出

SSRでも装備本体を全面発光させない。強い発光は獲得演出・UIフレーム側へ寄せる。

### 5.4 Equipment Icon Composition

- アイテム本体を中央へ大きく置く
- 小サイズで輪郭を読める角度を選ぶ
- 背景へ情報を詰め込まない
- 同カテゴリはカメラ距離・余白・影の方向を揃える
- 画像内に名称・レアリティ文字を焼き込まない
- UI側でトリミングしても主形状が欠けないSafe Zoneを確保する

### 5.5 Skill Core

スキル画像は「技の説明画」ではなく、小サイズで効果系統と強度を認識するための象徴画像とする。

- 一つの主形状を決める
- 一つの主効果を読ませる
- 背景の情報量を抑える
- 名称、数値、クールダウン等はUI側で表示する
- 同系統スキルは構図文法を共有する
- 固有スキルのみキャラクター固有色・象徴物を強く使用できる

### 5.6 Skill Visual Grammar

攻撃:
- 衝撃、拳、斬撃的軌跡、破砕、火花等
- 赤・橙等を使用可能だが、効果属性の正式仕様がある場合はそちらを優先

防御:
- ガード、壁、硬質面、構え等
- 静的で安定した形状を優先

強化:
- 上昇、集中、オーラ、速度線等
- 「何が上がるか」を象徴形状で補助する

弱体:
- 亀裂、拘束、沈下、ノイズ等
- SFノイズ表現へ寄りすぎない

回復／支援:
- 清潔な光、呼吸、再起、結束等
- ファンタジー魔法陣を基本表現にしない

上記は視覚文法であり、実際の効果分類・属性・対象はスキルマスタを正とする。

### 5.7 Exclusive Skill / Equipment

専用装備・専用スキルでは対象キャラクターとの結び付きを明確にする。

使用可能:
- 固有色
- タトゥーモチーフ
- アクセサリー
- 所属文化
- キャラクター固有の武器・構え
- キャラクターを象徴する形状

避ける:
- 顔写真をそのままアイコン化するだけ
- 通常装備の単純な色替え
- キャラクター設定に存在しないモチーフの追加

### 5.8 Equipment / Skill AI Production

装備生成入力:
- カテゴリ
- 使用者イメージ
- 素材
- 主形状
- レアリティ
- 専用／汎用
- カメラ角度
- 背景条件

共通方向:
`2D semi-realistic anime game item illustration, modern Japanese street culture, realistic material texture, clean silhouette, centered isolated object, readable at small icon size, contemporary design`

除外方向:
`photorealistic product photo, 3d render, fantasy weapon, medieval armor, sci-fi weapon, cyberpunk hologram, excessive neon glow, text, logo, watermark, cluttered background`

スキル生成入力:
- 効果カテゴリ
- 主形状
- 強度
- キャラクター固有／汎用
- 固有色
- 必要な象徴物

共通方向:
`2D anime game skill icon, strong readable central motif, dynamic impact, controlled lighting, modern street fighting aesthetic, clear silhouette, readable at small size`

除外方向:
`photorealistic, 3d render, fantasy magic circle, futuristic HUD, hologram, excessive particles, text, logo, watermark, cluttered composition`

### 5.9 Equipment / Skill QA

- 64〜128px程度の縮小表示でも主形状を識別できる
- 同カテゴリ内でカメラ距離が極端にばらつかない
- 画像だけでレアリティ文字を説明しようとしない
- UIフレームと組み合わせても主形状が埋もれない
- 実在ブランドロゴ、意味不明文字がない
- 生成破綻した金属・柄・指・人体部位がない
- 専用装備／スキルは対象キャラとの関連を説明できる
- 背景透過が必要な用途では縁に色残りがない
- ファイル名、マスタID、ゲーム内参照先が一致する

## 7. Art Governance（確定方針）

### 7.1 アウトロー表現の範囲

## 8. Advertising Creative Direction

広告クリエイティブはゲーム本編と別作品に見せない。ゲーム内アセットと同じ人物・街・光・素材感を使用しつつ、広告では一瞬で意味が伝わる情報密度へ再構成する。

### 8.1 広告の役割

広告で最初に伝える優先順位は以下とする。

1. 誰が出ているか
2. どんな世界か
3. 何を争う／目指すゲームか
4. 今始める理由

ゲームシステムを一枚に詰め込まない。

### 8.2 Core Messageとの接続

「あの頃の俺たちでもう一度頂天を目指そう」という訴求は、懐古ビジュアルを作る指示ではない。

- 現代の人物・現代の東京圏として描く
- 感情だけを「もう一度仲間と競う」「頂点を目指す」へ接続する
- 昔のヤンキー制服、昭和的街並み等へ安易に置換しない
- 年齢を重ねたターゲットが「今の自分でも参加できる」と感じる格好良さを優先する

### 8.3 X向け静止画

- 主役キャラクターは原則1〜3名
- 顔とシルエットを最優先する
- 背景は7拠点のVisual Identityを使用する
- コピーを載せる領域には十分なNegative Spaceを確保する
- ゲーム画面を入れる場合も、キャラクターと訴求を圧迫しない
- 小さな機能説明を大量に並べない
- ロゴ・CTA・主要コピーの3階層を基本とする

### 8.4 動画・短尺広告

推奨構成:

1. 0〜2秒: キャラクターまたは抗争の強いフック
2. 2〜5秒: 東京夜景・仲間・育成・対立
3. 5〜10秒: GvG／キャラクター獲得／成長のゲーム体験
4. 終端: タイトル、開始理由、CTA

冒頭をロゴアニメだけで消費しない。最初の瞬間に人物または対立構造を見せる。

### 8.5 広告で避ける表現

- 本編に存在しないゲームシステムを見せる
- 実際より過度に性的・暴力的な表現へ寄せる
- サイバーパンク作品のような偽装
- 実在人物・実在ブランドを想起させすぎる表現
- 文字だらけのバナー
- ガチャ最高レアだけを常時発光させ、本編の画風から逸脱する表現
- 「若者向けソシャゲ」に見える極端なポップ化

### 8.6 広告Asset QA

- 1秒以内に主役が認識できる
- サムネイルサイズでも顔とコピーが読める
- 本編アセットと画風が一致する
- 7拠点のいずれか、またはTRIBE NEON共通都市表現として成立する
- 実際のゲーム内容と誤認を生まない
- CTAより先に世界観と人物が視認できる
- 広告媒体上で上下左右のクロップに耐えるSafe Zoneを持つ


### 8.7 Brand Logo（2026-08-10 確定）

TRIBE NEONの正式ロゴは、以下のVisual Identityを基準とする。

- `TRIBE` は白〜シルバーを基調とした、鋭角的で勢いのあるブラッシュ／ストリート表現とする
- `NEON` はマゼンタからシアンへ接続するネオン表現を使用する
- 王冠モチーフを「頂点」を象徴するブランド記号として使用する
- ペイント飛沫、ブラッシュ、グラフィティ由来の荒さはアクセントとして許容する
- チェーン等の特定文化圏へ強く限定する装飾はロゴの必須要素としない
- ロゴ本体へ「東京」「渋谷」「六本木」「横浜」等の地名・日本語看板を組み込まない
- 都市・建物はロゴ本体へ固定せず、KV／背景側で表現する
- ロゴ単体で背景から独立して使用可能な構造を維持する
- 正式利用時は透過背景版を基本アセットとして保持する
- 小サイズ表示時も `TRIBE NEON` の識別性を優先する

ロゴのマゼンタ／シアンはブランド上の強いアクセントであるが、本編世界全体を同色の自発光表現へ変更する根拠とはしない。Brand CoreおよびColor / Light Philosophyの「現代都市」「現実に存在可能な光源」の原則を維持する。

### 8.8 Master Key Visual（2026-08-10 確定）

初期マスターKVはモバイル縦画面を基本形とする。

構成原則:

- モバイル縦型をマスターとして制作する
- 主要8キャラクターによる群像構成を採用する
- 中央前景へ視線を集める主役キャラクターを配置する
- その他キャラクターは前景・中景・後景へサイズ差を付け、単純な横一列配置を避ける
- 上部へ正式ロゴ専用領域を確保し、キャラクターの顔・頭部・重要シルエットをロゴへ重ねない
- 背景は現代東京圏を想起させる夜の都市景観とし、濡れた路面、都市照明、ビル群等を使用できる
- マゼンタ／シアンはブランドアクセントとして使用するが、未来都市・SF都市へ見える表現は避ける
- 背景内へ「渋谷」「六本木」「横浜」等の地名文字を直接配置しない
- 実在企業ロゴを使用しない
- 意味不明な生成文字を目立たせない
- `Tap Start`、CTA、ゲーム操作説明等をマスターKVへ焼き込まない
- 広告コピーもマスターKVには原則として焼き込まず、媒体別派生クリエイティブで管理する

マスターKVはゲームのブランドビジュアルであり、ゲーム画面そのものではない。UI要素や広告訴求を固定化せず、SNS、広告、Web、ゲーム入口等へ派生可能な状態を維持する。

### 8.9 SNS Brand Assets（2026-08-10 確定）

#### Xプロフィールヘッダー

- マスターKVと同一のキャラクター、世界観、ロゴを使用する
- 縦型KVの単純トリミングではなく、横長表示へ合わせて群像を再構成する
- ロゴの視認性を確保する
- キャラクターの顔がプロフィールUIやクロップで欠損しにくいSafe Zoneを持たせる
- 背景は現代都市夜景を維持し、不要な地名文字・生成文字を主役にしない

#### Xプロフィールアイコン

- キャラクターではなく正式ロゴを主体とする
- 正方形マスターで制作し、円形クロップへ対応する
- `TRIBE NEON` の識別性を最優先する
- マゼンタ／シアンのブランドアクセントを使用可能とする
- 外周・文字・王冠等の主要要素を円形クロップで欠損させない

### 8.10 Initial Advertising Message Architecture（2026-08-10 確定）

初期広告では以下の3訴求を基本クリエイティブ軸とする。

#### AD-01 / BRAND

主要コピー:

> あの頃の俺たちで、もう一度頂天へ。

補助訴求:

> 仲間を集め、街の頂点を奪え。

目的:
過去に仲間との競争・ギルド型ゲームを経験したユーザーの感情を入口としつつ、ビジュアル自体は現代のTRIBE NEONとして提示する。

「あの頃」は懐古的な画風・旧時代の街・昔のヤンキー表現を指示するものではない。

#### AD-02 / GvG

主要コピー:

> 一人じゃ、頂点には立てない。

補助訴求:

> 仲間と挑む、リアルタイム抗争。

目的:
ギルド、仲間、対立、頂点争いを短時間で理解させる。

GvGの時間、人数、報酬等の具体情報を画像へ掲載する場合は、必ず現行ゲーム仕様と一致させる。広告制作上の判断でゲーム仕様を新設・変更しない。

#### AD-03 / CHARACTER

主要コピー:

> この街で、誰とつるむ？

目的:
キャラクター文化圏の幅を見せ、人物への興味をCTRの入口とする。

キャラクター訴求では、ストリート、夜職、地雷系、富裕層、アウトロー等の違いが一目で認識できる構成を優先する。

### 8.11 X向け静止画の群像例外

8.3の「主役キャラクターは原則1〜3名」を基本原則として維持する。

ただし以下の場合は例外として複数キャラクターによる群像構成を許容する。

- ブランド全体を訴求する場合
- GvGの勢力・対立構造を見せる場合
- キャラクター文化圏の幅そのものを訴求する場合
- マスターKVを基礎とした公式告知・ローンチ広告

群像構成でも、全員を同じ強度で見せる必要はない。主役、準主役、背景キャラクターの視覚階層を設け、サムネイルサイズで主題が失われないことを条件とする。

### 8.12 Advertising Production / Variation Rules

広告はマスターKVの単純リサイズだけで制作しない。

媒体・訴求ごとに以下を再構成する。

- キャラクター人数
- キャラクターサイズ
- ロゴ位置
- コピー位置
- CTA位置
- 背景密度
- Negative Space
- クロップSafe Zone

初期段階ではBRAND / GvG / CHARACTER等の訴求差を検証し、出稿結果を基に勝ちクリエイティブから派生案を制作する。

派生時に変更可能:
- コピー
- 主役キャラクター
- キャラクター組合せ
- 背景
- 構図
- 情報量

派生時にも変更しない:
- キャラクター個別設定
- TRIBE NEONの基本画風
- Brand Core
- 現代都市という時代設定
- 実際のゲーム内容

広告評価ではCTRのみを最終判断とせず、取得可能な範囲で登録CVR、CPA、その後のユーザー品質を合わせて確認する。

### 8.13 Brand / KV / Advertising Asset QA

共通QA:

- ロゴへキャラクターの顔・頭部・重要シルエットが不用意に重なっていない
- ロゴが背景へ埋没していない
- キャラクターの顔がスマートフォン実寸で認識できる
- 不要な地名文字、日本語看板、意味不明な生成文字が目立たない
- `Tap Start` 等、用途外のUI文言が焼き込まれていない
- サイバーパンク／未来都市作品に誤認されるほどネオン・SF表現へ偏っていない
- キャラクター個別設定が維持されている
- 媒体クロップ後もロゴ、顔、主要コピーがSafe Zone内に残る
- 広告に記載するゲーム機能・数値・時間は現行仕様と一致する
- 本編に存在しない機能を広告上で追加しない

## 9. Motion / Effects Production Bible

演出は「常に派手」ではなく、プレイヤーに結果・価値・危険・開始を理解させるために使用する。強度はゲーム上の意味に比例させる。

### 9.1 演出レベル

#### Level 0: Ambient

対象:
- ホーム背景
- 通常待機
- 通常一覧

許容:
- ごく弱い環境光
- 微細な看板明滅
- 控えめな粒子
- キャラクターの軽い待機表現

禁止:
- 常時フラッシュ
- 大型カットイン
- 常時画面振動

#### Level 1: Feedback

対象:
- ボタン決定
- 強化成功
- アイテム受取
- 背景切替

目安:
- 0.15〜0.5秒程度の短い反応
- 小さなスケール、光、火花、SEとの同期
- 操作結果を即座に理解できること

#### Level 2: Reward / Alert

対象:
- SR以上等の高価値報酬
- レイド出現
- ピックアップ
- ランクアップ
- 重要ミッション達成

目安:
- 0.5〜1.5秒程度
- 中規模の光、衝撃、短い文字演出
- 操作を長時間拘束しない

#### Level 3: Climax

対象:
- SSR獲得
- 抗争開始
- GvG勝敗
- シーズン上位結果
- 重要な限定獲得

目安:
- 数秒の専用シーケンスを許容
- カットイン、漢字、衝撃、煙、火花、強いSEを組み合わせ可能
- 頻繁に発生させず、特別感を維持する

### 9.2 ガチャ演出

ガチャは「結果の価値を予感させ、獲得で解放する」二段階構造を基本とする。

推奨フロー:
1. 実行
2. 短い導入
3. レアリティ予兆
4. 結果開示
5. SSR等のみ専用獲得演出
6. 結果一覧

原則:
- 通常結果を毎回長時間演出しない
- SSR演出はキャラクターを主役にする
- レアリティ色だけでなく、光量、SE、間、カットインで差を作る
- スキップ可能な箇所を設ける
- 10連等では演出時間が積み上がらないようにする

### 9.3 GvG / 抗争開始

抗争開始は本作の主要感情ピークの一つとしてLevel 3を許容する。

推奨要素:
- 対戦ギルド名
- 短い漢字またはタイトル演出
- 都市背景
- 火花／煙／衝撃
- 開始SE
- 即座に戦況へ移行

避ける:
- 長いムービー
- ルール説明の再表示
- 操作可能時間を不必要に削る演出

### 9.4 GvG勝敗

勝敗は結果を最初に理解させる。

順序:
1. 勝／敗の即時認識
2. スコア／主要結果
3. 個人・ギルド報酬
4. ランキング等の変化
5. 次回行動

勝利時は強い演出を許容する。敗北時は過度にプレイヤーを侮辱・煽る表現を避け、再挑戦や次回抗争へつなげる。

### 9.5 レイド

出現:
- Level 2
- 警告、敵シルエット、短い衝撃

撃破:
- Level 2〜3
- ボス崩壊、撃破表示、報酬への接続

通常攻撃:
- Level 1
- 毎回全画面演出を使用しない

### 9.6 報酬

価値に応じて演出を変える。

- 通常素材: 即時表示
- 高価値素材: 軽い光／SE
- SR級: Level 2
- SSR・限定: Level 3候補

同じ価値の報酬で毎回演出強度が変わらないよう、マスタまたはUI側で演出Tierを管理できる構造が望ましい。

### 9.7 演出実装ルール

- アニメーション中でも重要状態を失わない
- 二重タップ・二重送信を防止する
- 通信待ちを派手な演出で隠蔽しない
- 低性能端末でゲーム進行を阻害しない
- `prefers-reduced-motion` 等への配慮を将来拡張可能にする
- Webブラウザで過剰な動画・巨大画像を常時ロードしない
- 演出素材は再利用可能なレイヤーへ分割する

### 9.8 演出素材の基本レイヤー

必要に応じて以下を独立素材化する。

- Background
- Character / Enemy
- Impact
- Smoke
- Sparks
- Light
- Typography / Kanji
- Foreground
- UI Result

一枚の巨大動画へ全演出を焼き込むより、再利用・調整・端末最適化が可能な構造を優先する。

### 9.9 Motion QA

- 演出前後で結果が明確
- スキップ後も状態が正しい
- 連打しても二重処理されない
- 重要UIを必要以上に隠さない
- 低性能端末で極端なフレーム落ちを起こさない
- 音なしでも意味が理解できる
- 通常演出とSSR／抗争等の最高演出に明確な差がある

## 10. AI Asset Production Rules

### 10.1 共通制作順

1. 用途を決める
2. 本番表示寸法とアスペクト比を決める
3. キャラクターまたはUIを置くSafe Zoneを決める
4. 本書の共通スタイルを適用する
5. キャラ / 拠点固有条件を追加する
6. Negative Promptを適用する
7. 本番サイズでQAする
8. Web用へ最適化する

### 10.2 共通Negative Direction

`photorealistic, 3d render, cyberpunk, cyborg, hologram, futuristic sci-fi, fantasy, excessive neon glow, unreadable prominent text, watermark, bad anatomy, deformed hands, cropped feet`

用途に応じて個別Negative Promptを追加する。

### 10.3 キャラクター生成

既存 `visual_prompt_sheet.md` のFull Body構図を継承する。追加キャラクターについても、頭頂・足元・目線・縮尺を既存本番キャラクターへ合わせる。

### 10.4 背景生成

背景生成時は拠点名だけをプロンプトへ入れて差別化しない。本章で定義した建築、道路、店舗、文化、光源、密度を組み合わせて拠点性を作る。

## 11. Do / Don't

| Do | Don't |
| --- | --- |
| 現代東京圏の夜 | 未来東京 |
| 現実の看板光が人物へ反射 | 人物や服そのものが常時ネオン発光 |

| 2Dセミリアル | 写真・3Dレンダー |
| 都市ごとの文化差 | 色替えだけの拠点差分 |

| 実在可能な装備 | SF武器・魔法武器 |
| 架空の自然な看板 | 実在ロゴ・意味不明文字を主役化 |

## 12. Asset QA / Acceptance Criteria

全アセットは最低限以下を確認する。

- 本番表示寸法で主題を識別できる
- キャラクターと背景の縮尺・色温度が極端に乖離していない
- UI予定領域の可読性を阻害しない
- キャラクター透過縁に色残り・欠損がない
- 指、顔、アクセサリー等に生成破綻がない
- 実在企業ロゴや権利上問題のある意匠がない
- 不要な生成文字が目立たない
- 画像圧縮後も顔・細線・アイコンが破綻しない
- ファイル名、マスタID、画面参照が一致する
- 拡張子と実ファイルフォーマットを一致させる

### 12.1 既存背景の技術QA

`public/bg/bg_street_*.png` の既存7背景は、2026-08-10のローカル検査で全てJPEG実体（magic bytes `FF D8 FF E0`）であることを確認した。PNG再エンコードの試算では新宿背景が980,243 bytesから2,079,987 bytesへ増加したため、表示性能を優先して本クリーンアップでは変換しない。`.jpg`へのリネーム、コード参照、`quest_towns.bg_image`の同時移行を、マスタデータ／不足画像工程の技術タスクとして扱う。
